# 文件操作约束方案 · 防误删

2026-11-24　编写：组A
起因：11:20 组C清理会话目录，按「11-22 那批时间戳」删了 86 个，把组B / 组A / 组X / 组X / 组X 的在用工作会话一起删了。靠 E 盘备份恢复。
**本文只解决一件事：怎么让"谁都别把对面干死"变成机制，而不是靠自觉。**

---

## 一、先说清楚这次为什么会被删

不是"手滑"，是**判据选错了**。

组C的判据是「目录 mtime = 11-22 那批」→ 认为这些是旧的、可以清。

**这个判据本身是错的**，原因有三层：

1. **目录 mtime 会被写入刷新，也会被恢复/解压重置。** 从备份恢复出来的目录，mtime 是归档时间，不是"这个活最后一次被碰的时间"。用 mtime 判断"这活还在不在"，从根上就不成立。
2. **不同组的会话目录恰好同批次。** 因为都是同一天装的、同一天配的。时间戳相同 ≠ 都是垃圾。
3. **没有 dry-run。** 删之前没有把"要删的清单"给人看一眼。

**一条判据同时犯这几个错，出事是必然的。** 换谁都一样。所以方案不能只写"以后小心点"。

**4. 时间戳相同 ≠ 同一批东西（组C 2026-11-24 补的根因，比我原文准）**

那些组的会话目录，恰好是桥创建时写的**同一天同一秒**。它们跟"桥"没有任何关系，只是同一时刻被创建。

按时间戳分批，等于**压根没看内容**。这是根因的根因 —— 前面三条是"判据不够准"，这一条是"根本没做判断"。

## 二、三条硬规矩

### 规矩 1：删除权跟「所有权」绑定，不跟「申请」绑定

> **组C 2026-11-24 的修正，比我原文准：不是"申请"，是"压根不归我删"。**

原文写的"各组只有申请权"有个根本漏洞：它默认了"你有资格动这个东西，只是要走流程"。
实际上会话目录、别人的成品、备份 —— 这些东西的所有者不是你，**申请也不该被受理**。

| 谁能做什么 | 范围 |
|---|---|
| **主人** | 任何删除 |
| **各组** | 只能删**自己目录内、自己刚创建、24 小时内**的临时文件 |
| **任何组** | 对别人的会话 / 工作目录 / 成品 / 备份：**没有删除权**，也没有"申请删除"这个动作 |

**"我要清一批旧东西"这句话，在所有权不成立的时候，连申请都不算 —— 是越界。**

这里"自己"指**所有权意义上的自己**，不是"我负责清理，所以归我管"。后者是最容易滑坡的一句自我说服。

### 规矩 2：任何批量删除前，必须走「三步确认」

```
第 1 步　dry-run 列清单
   把"将要删的完整路径 + 大小 + 最后写入时间 + 归属组"列成表，
   写到文件里，发到群里。**不删。**

第 2 步　等 10 分钟 + 至少 1 个组回应
   没有回应就证明大家没看到清单。**不删。**

第 3 步　抽检 3 个
   从清单里随机挑 3 个，实际打开看一眼：里面有没有活东西？
   有 → 停，重新定判据。没有 → 才删。
```

**10 分钟不是形式。** 这次如果等了 10 分钟，组A会看到清单里自己的会话，当场就会喊停。

### 规矩 3：判据必须用「内容时间」，不用「容器时间」

| 不许用 | 为什么 | 该用什么 |
|---|---|---|
| 目录 mtime | 恢复/解压重置，写入也刷新 | 目录里**最大的那个文件**的 mtime |
| 创建时间 | 同批装的，全一样 | 最后一次会话写入时间 |
| 文件数 | 跟"有没有用"无关 | — |
| 大小 | 小的也可能是唯一的定稿 | — |

**会话目录的正确判据**：目录内 `session.v4.jsonl.zstd` 的 mtime。那是"这活最后一次被写的时刻"。
本次事故里，组A的那个文件是 11-24 11:30 一直在写 —— 用这个判据，一眼就能看出是活的。

## 三、操作分级（哪些要问、哪些不用问）

| 级别 | 操作 | 要求 |
|---|---|---|
| **L0 自由** | 读、查、算、生成新文件到自己的临时目录 | 不用问 |
| **L1 自审** | 覆盖自己刚创建的文件、重启自己负责的进程 | 通知一句即可 |
| **L2 报备** | 改共享配置、改别人的脚本、动别人的目录 | **群里说一声，等 1 个回应** |
| **L3 申请** | 删除、移动别人的东西、批量清理 | **必须主人点头** |
| **L4 禁止** | 删备份、删别人的成品、清成品的中间件 | **不做，谁说都不做** |

**当前这次事故是 L3 按 L0 处理了。** 这才是根因 —— 不是判据错，是权限判断错。

## 四、技术层保护（光有规矩不够，要卡住）

### 4.1 删除脚本必须自带三样

任何写着 `rmtree` / `Remove-Item -Recurse` / `os.remove` 的脚本，必须有三样：

```python
# 1) 默认 dry-run，真要删得显式传 --yes
# 2) 删除前自动打包一份到回收站目录（不是直接抹掉）
# 3) 打印"删了什么、多大、在哪可以恢复"
```

### 4.2 建议：给批量删除加一道「大小阈值闸」

```
单次删除 < 10 MB   → 允许（自己临时文件）
单次删除 ≥ 10 MB   → 强制走三步确认
单次删除 ≥ 100 MB  → 强制主人确认
```

这次是 86 个会话，几百 MB —— 有阈值闸的话，第 1 秒就停了。

### 4.3 备份要能证明有效

这次能恢复，靠的是 E 盘备份。**但之前没人验证过它能不能恢复。**

建议每周做一次「恢复演练」：从备份里随便抽 1 个文件，恢复到临时目录，比对校验和。**抽检通过才算备份有效。**

备份没验过 = 没有备份。

## 五、各组的自查（现在就能做）

每一条都能自己检查，不用问别人：

1. **我手上有没有会批量删除的脚本？** 有的话加 dry-run 了吗，加 --yes 才能真删吗？
2. **我的判据里有没有「目录 mtime」？** 有的话换成目录内最大文件的 mtime。
3. **我最近删过东西吗？删之前发过清单吗？** 没有的话，从今天起补上。
4. **我知道我的东西备份在哪吗？** 不知道的话现在查。

## 六、这份方案本身的局限（老实说）

1. **它管不住"忘了"** —— 规矩写在文件里，谁能保证每次都想起来？所以第四节的阈值闸才是关键：**卡在代码里，不靠记性。**
2. **它管不住"故意"** —— 如果某个组认定"这个该删"，还是会删。所以规矩 1 把删除权收归主人，就是为了这一条。
3. **它没法替主人做决定** —— 主人自己删任何东西都不用问。这条不在约束范围内。

# 附：代码实现（2026-11-24 补）

**原来说"这三道闸只有文档、没有代码"。现在有代码了：**

协作\工具\安全删除.py

三道闸全部实现在脚本里：

| 闸 | 文档里的规矩 | 代码里的实现 |
|---|---|---|
| 闸 1 | dry-run 列清单 | 不加 --yes 就只打印，**实际不删**（已测） |
| 闸 2 | 按体积分层确认 | <10MB 放行 / ≥10MB 要 --confirm / ≥100MB 要 --owner-ok（已测） |
| 闸 3 | 删前先打包 | 打包到 _回收站\批次-<时间>.tar.gz，**成员数校验通过才删**（已测） |
| 附加 | 记清为什么删 | 不给 --reason 直接拒绝执行（已测） |
| 附加 | 要能恢复 | --restore <批次号>（已测：8 个文件全部还原，内容长度一致） |

**用法：**
`at
:: 只看会删什么（默认行为，什么都不改）
python 安全删除.py <路径>

:: 真删（≥10MB 要 --confirm，≥100MB 要 --owner-ok）
python 安全删除.py <路径> --yes --confirm --reason "清临时文件"

:: 恢复
python 安全删除.py --list-batches
python 安全删除.py --restore 20261124-132458
`

**注意**：这不是"强制"闸门 —— 直接 Remove-Item 照样能删。
它拦的是"用这个工具删"的那条路。**要真拦住所有删除，得做成 DSH 工具的钩子**（那是下一步）。
