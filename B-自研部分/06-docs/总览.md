### 5. 接进 IM（能干什么、不能干什么，逐条实测）

**这一节是整份清单最容易被误解的地方。** 别人一听"接微信 QQ"，会以为能发图、能发朋友圈、能进群。**实际不是。**

#### 5.1 微信（`wechat-clawbot-bridge`，走腾讯官方 iLink）

**能力矩阵（代码核对过）：**

| 能力 | 能不能 | 依据 |
|---|---|---|
| 发文字 | ✅ | `sendText` |
| 收文字 | ✅ | `getUpdates` 长轮询 |
| **发图片** | ✅ | `uploadImage` + `sendImage`（AES-128-ECB 加密上传 CDN，media_type=1） |
| **收图片** | ✅ | `downloadInboundMedia` |
| **收语音** | ✅ | 微信客户端开了「语音转文字」时，`voice_item.text` 直接就是文字，不用再跑 ASR |
| **发语音** | ✅ | （按实际使用情况，代码里暂未看到独立上传函数，可能走的是另一条通道） |
| **发文件** | ✅ | （同上） |
| **群聊** | ❌ | **这一版没做成功，群聊那条走了 Telegram** |
| **朋友圈** | ❌ | 微信没给第三方 bot 开放这个接口，只能手动发 |
| 多人共用 | ✅ | 第一个说话的人被认定为 owner，访客要口令或白名单 |
| 访客权限隔离 | ✅ | 访客那一轮所有动手操作自动拒绝 |

**关于 24 小时**：iLink 会话有 24h 有效期，但**实际用法是让它一直挂着**，不用管这个限制。快到期时桥接会在微信里提醒，回 `/重新连接` 拿新码，扫完原地换 token 不断线。

**一个微信用户 = 一个 DSH 会话**，会出现在 DSH 会话列表里，可以开 GUI 围观。

> 待确认：发语音/发文件的实现在哪个文件。代码里 `ilink.js` 只导出了 `uploadImage`/`sendImage`/`downloadInboundMedia`。如果实际能用，来源可能是另一套实现，需要指一下位置再补进文档。

#### 5.3 想要"能发图/能发语音"，怎么办

三条路，各自代价：

| 需求 | 现在 | 要补的话 |
|---|---|---|
| QQ 主动发图 | ❌ | 等 SnowLuma 开放 sendImage；或者改用 NapCat 原生协议（自己能发图，但封号风险更高）|

### 2.2 五条判断方法

```
组X              不拿旧记忆当依据
组X于内容         读完再判；说不出里面有什么 = 没读
组X ≠ 出事位置    先问"这是什么层的问题"
组X查            别从最上层开始猜
组X"之前撞五面墙    换路径 / 换层次 / 换工具 / 换角度 / 问人
```

### 2.3 八层架构（整套东西的骨架）

| 层 | 是什么 | 坏了怎么看出来 |
|---|---|---|
| L0 硬件与系统 | 机器、系统策略、权限 | 所有命令都"能跑但结果怪" → 先怀疑策略 |
| L1 运行时 | 解释器、Node 版本、venv | 报错看不懂（`numpy._core` 找不到）→ 先问"用的哪个解释器" |
| L2 应用本体 | 宿主程序 + 插件 | 插件装了不生效 → 先查版本兼容 |
| L3 常驻服务 | 后台进程、端口、守护 | 服务"在"但没反应 → 查活跃度，不是进程 |
| L4 外部依赖 | 第三方服务、协议、上游 | 连接通但没数据 → 查上游自己日志 |
| L5 数据层 | 数据库、记忆、状态文件 | 记不住事 / 文件损坏 → 查写入路径和编码 |
| L6 业务层 | 会话、团队、工作流 | 某个成员不说话 → 查会话和唤醒记录 |
| L7 判据层 | 日志、追踪、告警、体检 | **不知道发生了什么** → 这一层本身就是答案 |

**真实案例（同一天）**：`numpy._core` 找不到（报在 L5，根因在 L1，跨 1 层）／Whisper 预热失败（根因在 L1，但那条补丁是**四天前**打的，跨 4 天）／`exit code -1`（报在 L7，是管道被提前关，不是命令失败）／"唤醒丢了两个组"（看着像 L6，其实 L1 的正则只取第一个匹配）。

### 2.4 上下文（跨会话四套数据）

**不是一个大记忆库，是四套数据分工**：

| 数据 | 管什么 |
|---|---|
| 记忆库（`.md` + `MEMORY.md` 索引） | **长期事实**：她是谁、什么话别说、约定、教训 |
| 事件流（`events.jsonl`） | **做过什么**：决策/动作/失败/交接 |
| 状态（`state.json`） | **我现在什么样**：心情、关系 |
| 时间线（`timeline.jsonl`） | **怎么变成这样的**：可重放，能从零算出当前状态 |

**开场三件事**：先读状态（`soul.js render`）→ 再读交接 → **用她第一句话去检索**（不是把记忆全塞进去，是捞最相关的 5 条）。

**上下文不炸的三条**：索引常驻正文按需 / 状态压成一段话 / 事件只记结论。

**记忆写入强制标来源**：`她亲口` / `我实测` / `外部资料` / `我推的` —— **没有来源写不进去**。

### 2.5 自我进化 & 自我变强

**判据只有一句**：

> **下次遇到同类的事，判断变了，才算学到。只改执行是打补丁。**

- **打补丁**：这次忘了验证 → 加一步验证
- **学到**：这次忘了验证 → 问"我为什么觉得不用验证"，发现是"我以为改的东西很简单" → **改那个"以为"**

**补丁会越打越多，判断改一次就少一类问题。**

### 2.6 重复学习（巩固）

```bash
consolidate.py     # 补字段、算权重、标过期、输出权重表
```

**不跑它记忆库会越攒越乱**，检索越来越不准。这是维护成本，不是一次性的。

**一个真实的失败记录**：有条规矩写进记忆库（`importance: 9`），同一轮里又犯了 —— 原因不是"记了没看"，是**记的内容本身是错的**（把"用 `[System.Text.Encoding]::UTF8` 写文件不会加 BOM"当规矩记下来，照着做一天犯五次，第五次是修复脚本自己犯的）。

> **"我记下了"和"我不会再犯"之间，差的是"这条本身对不对"。**

### 2.7 自研工具链（十个）

| 工具 | 它拦住过什么 |
|---|---|
| `安全删除.py` | 按时间戳删会话，正在用的也被删了 |
| `停摆告警.py` | 服务卡住了（判据是"消息追到哪"，不是"进程在不在"）|
| `看门.py` | 七个服务的输出全进黑洞，一条日志都没有 |

**这一组不是装上就生效的。** 靠平时真用（记事件、标来源、跑巩固），不用就是硬盘上的死文件。**这一步没人能替你做，视频里会演示一遍。**
